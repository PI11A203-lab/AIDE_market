# AI 판매자(Admin) 회원가입 구현 계획서

## 📋 현재 시스템 분석

### 1. 데이터베이스 구조 (User 모델)
- **role**: `ENUM('admin', 'user')` - 기본값: `'user'`
- **account_type**: `ENUM('general', 'student', 'corporate')` - 기본값: `'general'`
- **기본 필드**: username, email, password_hash, profile_image, bio, github_url 등

### 2. 현재 회원가입 흐름
- **프론트엔드**: `SignupForm.js` → `role: 'user'`로 고정하여 전송
- **백엔드**: `userController.createUser()` → role 파라미터를 받아서 처리 (기본값 'user')

### 3. 임시 계정 정보
- **이메일**: `admin@email.com`
- **비밀번호**: `adminadmin`
- **권한**: `admin` (AI 판매자)

## 🎯 구현 목표

AI 판매자(Admin 권한)로 회원가입할 수 있는 기능 구현

---

## 📝 구현 방안

### 방안 1: 별도의 판매자 회원가입 페이지 생성 (권장)
**장점:**
- 일반 사용자와 판매자를 명확히 구분
- UI/UX를 판매자에 맞게 최적화 가능
- 보안상 더 안전 (일반 사용자가 admin 권한으로 가입하는 것 방지)

**단점:**
- 추가 페이지 개발 필요

**구현 내용:**
1. `/signup-seller` 경로 추가
2. `SignupSellerForm` 컴포넌트 생성
3. 회원가입 시 `role: 'admin'` 전송
4. `account_type: 'corporate'` 설정 (선택사항)

---

### 방안 2: 기존 회원가입 페이지에 판매자 옵션 추가
**장점:**
- 하나의 페이지로 통합 관리
- 개발 시간 단축

**단점:**
- 일반 사용자가 실수로 admin 권한으로 가입할 수 있음
- 보안 위험

**구현 내용:**
1. `SignupForm`에 "판매자로 가입" 체크박스 추가
2. 체크 시 `role: 'admin'` 전송
3. 추가 인증 절차 필요 (예: 관리자 승인)

---

### 방안 3: 백엔드에서 특정 이메일/비밀번호로 자동 admin 권한 부여
**장점:**
- 프론트엔드 변경 최소화
- 특정 계정만 admin 권한 부여 가능

**단점:**
- 하드코딩된 로직 (유연성 부족)
- 이메일/비밀번호 변경 시 코드 수정 필요

**구현 내용:**
1. `userService.createUser()`에서 특정 이메일(`admin@email.com`) 체크
2. 해당 이메일이면 자동으로 `role: 'admin'` 설정

## 🔐 보안 고려사항

### 1. 현재 방안의 보안 취약점
- 특정 이메일만으로 admin 권한 부여는 보안상 위험할 수 있음
- 이메일 주소는 변경 가능하므로, 이메일 변경 시 권한 유지 여부 확인 필요

### 2. 보안 강화 방안
- **환경 변수 관리**: `.env` 파일에 관리자 이메일 목록 저장
- **비밀번호 검증**: 특정 비밀번호 조합 필요
- **IP 화이트리스트**: 특정 IP에서만 관리자 계정 생성 허용
- **추가 인증**: 관리자 승인 프로세스 추가

### 3. 권장 보안 설정
```javascript
// .env 파일
ADMIN_EMAILS=admin@email.com,admin2@email.com
ADMIN_PASSWORD=adminadmin
ALLOW_ADMIN_SIGNUP=true  // 개발 환경에서만 true
```
