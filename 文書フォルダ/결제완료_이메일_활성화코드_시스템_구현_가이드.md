# 결제 완료 이메일 및 활성화 코드 시스템 구현 가이드

## 📋 요구사항

1. **결제 완료 시 이메일 발송**: 주문이 완료되면 고객에게 결제 내용과 활성화 코드를 이메일로 전송
2. **상품별 활성화 코드 생성**: 각 상품마다 랜덤한 32자리 활성화 코드 자동 생성
3. **정기결제 시 코드 유지**: 정기결제인 경우 기존 활성화 코드를 그대로 유지 (새로 생성하지 않음)

---

## 🔍 현재 시스템 상태 분석

### ✅ 이미 구현되어 있는 것들

1. **ProductActivation 모델 및 서비스**
   - `productActivationService.js`에 활성화 코드 생성 로직 존재
   - `generateActivationCode()`: 32자리 랜덤 코드 생성 (crypto.randomBytes 사용)
   - `createActivation()`: 단일 활성화 코드 생성
   - `createActivationsForSubscription()`: 구독에 대한 활성화 코드 일괄 생성

2. **이메일 서비스**
   - `emailService.js`에 이메일 발송 기능 존재
   - `sendPaymentSuccessEmail()`: 결제 성공 이메일 (기본 구현됨)
   - `sendSubscriptionCreatedEmail()`: 구독 생성 이메일 (기본 구현됨)
   - 다국어 지원 (ko, en, ja)

3. **정기결제 시스템**
   - `subscriptionService.js`에 정기결제 로직 구현됨
   - `createSubscription()`: 구독 생성
   - `processMonthlyPayment()`: 월별 자동 결제 처리

### ❌ 현재 누락된 것들

1. **일반 주문 완료 시 이메일 발송**
   - 주문 생성 후 자동으로 이메일 발송하는 로직 없음
   - 활성화 코드를 이메일에 포함시키는 로직 없음

2. **정기결제 시 코드 유지 로직**
   - `processMonthlyPayment()`에서 결제 성공 시 기존 코드 재활성화는 하지만, 이메일에는 코드가 포함되지 않음
   - 정기결제 시 "기존 코드 유지" 메시지가 이메일에 명시되지 않음

3. **활성화 코드를 이메일 템플릿에 포함**
   - 현재 이메일 템플릿에 활성화 코드가 표시되지 않음

## 💾 데이터베이스 변경사항

### ✅ 현재 상태

모든 필요한 테이블과 컬럼이 이미 존재합니다:

1. **`product_activations` 테이블** - 이미 생성됨
   - `activation_code` (VARCHAR(100), UNIQUE) - 활성화 코드 저장
   - `subscription_id` (INT, NULL) - 정기결제 연결
   - `status` (ENUM) - active, suspended, expired, revoked
   - `activated_at`, `suspended_at` - 상태 변경 시각
   - 모든 필요한 인덱스 포함

2. **`orders` 테이블** - 필요한 컬럼 이미 추가됨
   - `subscription_id` - 구독 연결
   - `is_recurring` - 정기결제 여부
   - `is_first_payment` - 최초 결제 여부
   - `parent_order_id` - 최초 주문 ID

3. **`subscriptions` 테이블** - 이미 존재
   - 구독 정보 저장
   - 활성화 코드와 연결 가능

4. **`Users` 테이블** - 필요한 컬럼 존재
   - `preferred_language` - 사용자 언어 설정 (이메일 언어 결정)

#### 3. 정기결제 시 코드 유지를 위한 데이터 구조

**현재 구조 (이미 구현됨):**
- 최초 구독 생성 시: `createActivationsForSubscription()` 호출
  - 각 상품별로 활성화 코드 생성
  - `subscription_id`로 구독과 연결
  - `status = 'active'`

- 정기결제 실행 시: `processMonthlyPayment()` 호출
  - 결제 성공 시 `reactivateActivationsForSubscription()` 호출
  - **중요**: 새 코드 생성하지 않고 기존 코드의 `status`만 `'active'`로 변경
  - `activation_code`는 변경되지 않음 (동일 코드 유지)

### ⚠️ 주의사항

1. **중복 코드 방지**
   - `activation_code`는 UNIQUE 제약조건이 있으므로 중복 생성 방지됨
   - `generateActivationCode()` 함수에서 중복 확인 로직 포함

2. **정기결제 코드 유지**
   - `processMonthlyPayment()`에서는 **절대 새 코드를 생성하지 않음**
   - `reactivateActivationsForSubscription()`만 호출하여 기존 코드 재활성화

3. **트랜잭션 처리**
   - 주문 생성과 활성화 코드 생성을 같은 트랜잭션에서 처리
   - 이메일 발송은 트랜잭션 외부에서 처리 (실패해도 주문은 완료)

현재 DB 스키마로 모든 기능 구현이 가능합니다. 다만, 다음 사항을 확인하세요:

```sql
-- 3. subscription_id 컬럼이 있는지 확인

```

만약 테이블이 없다면, 다음 SQL을 실행:

```sql
CREATE TABLE product_activations (
  activation_id INT PRIMARY KEY AUTO_INCREMENT,
  user_id INT NOT NULL,
  product_id INT NOT NULL,
  order_id INT NOT NULL,
  subscription_id INT NULL,
  activation_code VARCHAR(100) NOT NULL UNIQUE,
  status ENUM('active', 'suspended', 'expired', 'revoked') DEFAULT 'active',
  activated_at DATETIME NULL,
  suspended_at DATETIME NULL,
  suspended_reason TEXT NULL,
  grace_period_end_date DATE NULL,
  expires_at DATETIME NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES Users(id),
  FOREIGN KEY (product_id) REFERENCES Products(id),
  FOREIGN KEY (order_id) REFERENCES orders(id),
  FOREIGN KEY (subscription_id) REFERENCES subscriptions(subscription_id),
  INDEX idx_user_id (user_id),
  INDEX idx_product_id (product_id),
  INDEX idx_activation_code (activation_code),
  INDEX idx_status (status),
  INDEX idx_subscription_id (subscription_id)
);
```

```javascript
/**
 * 주문 완료 이메일 발송 (일반 주문용)
 */
exports.sendOrderCompletionEmail = async (order, activations, baseUrl = 'http://localhost:3000') => {
    try {
        // 사용자 정보 조회
        const user = await models.User.findByPk(order.user_id);
        if (!user || !user.email) {
            console.log('사용자 이메일이 없어 이메일을 발송할 수 없습니다.');
            return;
        }

        const language = user.preferred_language || 'ko';
        const template = emailTemplates.orderCompletionTemplate(order, activations, language);

        const mailOptions = {
            from: process.env.EMAIL_FROM || 'noreply@aidemarket.com',
            to: user.email,
            subject: template.subject,
            html: template.html,
            text: template.text
        };

        await transporter.sendMail(mailOptions);
        console.log(`주문 완료 이메일 발송 완료: ${user.email}`);
    } catch (error) {
        console.error('주문 완료 이메일 발송 실패:', error);
        throw error;
    }
};
```

## ⚠️ 주의사항

1. **트랜잭션 처리**: 이메일 발송은 트랜잭션 외부에서 실행 (주문/결제는 완료 후 이메일 발송)
2. **에러 처리**: 이메일 발송 실패해도 주문/결제는 성공한 것으로 처리
3. **비동기 처리**: 이메일 발송은 비동기로 처리하여 응답 지연 방지
4. **중복 방지**: 활성화 코드 생성 시 중복 확인 로직 이미 구현되어 있음
5. **정기결제 코드 유지**: `processMonthlyPayment()`에서 새 코드 생성하지 않고 기존 코드만 재활성화
